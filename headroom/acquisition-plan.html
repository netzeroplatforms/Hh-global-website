HHeadroom 6-Month Acquisition Plan
Technical Roadmap · 6–9 Months

From Tool to Platform

Headroom is a feature today. To become acquisition-ready, it needs a backend, an API, a data moat, and proof that other platforms want to embed it. Here's the exact technical path.

The Goal: Make Headroom a "must-have bolt-on" for solar platforms

Current State

  • Single-page HTML app
  • No backend or API
  • No user accounts
  • No analytics
  • Google Solar API dependent
  • No data persistence

Target State

  • API-first architecture
  • Embeddable widget
  • Proprietary grid database
  • User analytics & traction
  • Multi-tenant SaaS
  • CI/CD + tests + docs

Ideal Buyers

  • EasyPV / Midsummer
  • Payaca
  • OpenSolar
  • Aurora Solar
  • Installer CRMs
  • Energy comparison sites
01
Foundation — Months 1–2
Phase 1

Stop being a webpage. Start being a platform. This phase is about architecture, not features.

Week 1–2
Backend + API
  • Deploy Node.js/Python backend (AWS/GCP/Heroku)
  • REST API: /capacity/{postcode}, /dno/{region}, /report/generate
  • Move all DNO logic from client to server
  • Database: PostgreSQL for lookups, Redis for caching
  • API key authentication for partners
Week 3–4
User Accounts & Analytics
  • JWT auth + basic user registration
  • Track: lookups, reports generated, shares
  • Simple admin dashboard (usage, top postcodes, active users)
  • Google Analytics + Mixpanel/Amplitude
Week 5–8
Code Quality & Documentation
  • Unit tests (Jest/Pytest) — target 70% coverage
  • CI/CD pipeline (GitHub Actions)
  • API documentation (Swagger/OpenAPI)
  • Architecture decision records (ADRs)
  • README + deployment guide
02
Product Hardening — Months 2–4
Phase 2

Build the moat. The data is the product. The API is the distribution.

Month 2–3
Proprietary Grid Database
  • Aggregate DNO capacity data from all 14 UK operators
  • Postcode-level mapping (not just region-level)
  • Historical queue data + wait times
  • Substation-level capacity where publicly available
  • Update pipeline (monthly refresh from DNO publications)
Month 3
Embeddable Widget
  • <iframe> widget: 2 lines of code to embed
  • White-label: custom colours, logo, domain
  • JavaScript SDK for deeper integration
  • Webhook support: post results to partner URL
Month 3–4
Advanced Modelling
  • Battery + solar co-location economics
  • Export tariff optimisation (Octopus Agile, etc.)
  • Self-consumption modelling
  • EV charger load impact
  • Heat pump + solar integration
Month 4
Reduce Google API Dependency
  • Build own roof/irradiance estimation (OS MasterMap + PVGIS)
  • Fallback pipeline: Google Solar → OS → manual entry
  • Cache all roof analysis results
  • Cost reduction: Google API is expensive at scale
03
Traction & Partnerships — Months 4–6
Phase 3

A product with no users is just code. A product with 50 partners and 10,000 lookups is an asset.

3.1 Free Tier + Viral Loop

Must
  • 50 free postcode lookups/month per user
  • Shareable report links (branded with Headroom)
  • "Powered by Headroom" badge on embeds
  • Installer directory: list users by region
Viral distribution through installer sharing with customers.

3.2 Partner API Pilots

Must
  • Target 5 solar platforms for API pilot
  • Offer free API access for 90 days
  • Co-marketing: "Headroom integrated with X"
  • Case study per integration
Priority targets: Payaca, OpenSolar, smaller CRMs hungry for differentiation.

3.3 Content & SEO

Nice
  • Blog: "DNO queue times by region" (monthly)
  • Interactive map: UK grid capacity heatmap
  • Press coverage: Solar Power Portal, PV Magazine
  • LinkedIn content from "Headroom team"
SEO + press = inbound buyer interest + validates market presence.

3.4 Installer Community

Nice
  • Facebook group / Discord for UK solar installers
  • Monthly "Grid Watch" newsletter
  • DNO queue time alerts by region
  • User feedback loop for product improvements
Community = retention + word of mouth + buyer confidence.
04
Sale Preparation — Months 6–9
Phase 4

Package it like a product, not a project. Buyers buy metrics, documentation, and low-risk integration.

4.1 Metrics Dashboard

Must
  • MAU / lookups per month
  • Partner integrations live
  • Postcodes covered (% of UK)
  • API uptime (target 99.9%)
  • Revenue (even if small — shows model works)
Buyers need numbers. Any numbers. Growth trajectory matters more than absolute size.

4.2 Data Room

Must
  • Source code + repo access
  • API docs + integration guides
  • Architecture diagrams
  • Database schema + data dictionary
  • User analytics export
  • IP ownership (clean)
Make due diligence trivial. A buyer who can integrate in a day is a buyer who pays more.

4.3 Buyer Outreach

Must
  • Warm intros to Payaca, OpenSolar, EasyPV
  • Cold outreach to Aurora Solar, Sunbase, AdminBase
  • VCs with solar/energy portfolio (BGF, Octopus Ventures)
  • Energy comparison sites (Uswitch, Compare the Market)
Position as "the grid capacity layer every solar platform needs."

4.4 Pricing Model

Nice
  • Free: 50 lookups/month
  • Pro: £49/month — unlimited + API
  • Partner: £199/month — white-label widget + SLA
  • Enterprise: custom — data feed + dedicated support
Even £500 MRR proves the model. Buyers multiply by 20–40x ARR for SaaS.

06
Week 1 Actions — Start NOW
Phase 1

The first 7 days determine whether this is a 6-month sprint or a 2-year death march.

Day 1–2: Decision

Must
  • Decide: build for sale, not for scale
  • Set 6-month deadline (hard)
  • Allocate 2 days/week max — don't over-invest
  • Budget: £5-10K for hosting, APIs, contractor help

Day 3–5: Backend Scaffold

Must
  • Spin up server (Render/Railway/AWS)
  • Move DNO lookup logic to API
  • Postgres + Redis
  • Deploy to staging

Day 6–7: First Partner Call

Must
  • Identify 5 target partners
  • Send 3 cold LinkedIn messages
  • Ask: "Would you embed a grid capacity widget?"
  • Document objections

Ongoing: Don't

Avoid
  • Don't rebuild the UI — it's fine
  • Don't add features no one asked for
  • Don't chase VC funding
  • Don't build a sales team
  • Don't register trademarks (waste of time)

Build the API. Aggregate the data. Prove the demand. Sell.

Headroom's value is not the UI. It's the grid intelligence layer underneath. Make that layer embeddable, and someone will buy it.
